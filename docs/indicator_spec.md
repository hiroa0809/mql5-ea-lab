## 1. スパンモデル

### 1.1 パラメータ（S3 の初期値）

| 要素 | 期間 | 既定色 |
|---|---|---|
| スパンA | 9 | 青 |
| スパンB | 52 | 赤 |
| 雲 | — | 雲色1 = 青 / 雲色2 = 赤 |
| 遅行線 | 26 | マゼンタ |

### 1.2 計算

```
転換線 = (Highest(High,  9) + Lowest(Low,  9)) / 2
基準線 = (Highest(High, 26) + Lowest(Low, 26)) / 2

スパンA = (転換線 + 基準線) / 2                        ← 一目均衡表の先行スパン1に相当
スパンB = (Highest(High, 52) + Lowest(Low, 52)) / 2    ← 一目均衡表の先行スパン2に相当
遅行線  = Close を 26 本前へずらして描画               ← 一目均衡表の遅行スパンと同一
```

UI のラベルは「スパンA[9]」だが、**実際には 26 も使う**（遅行線のパラメータ 26 が基準線の期間を兼ねている）。9 / 26 / 52 の3値で一目均衡表と同じ構成になる。

#### スパンA の式の確定根拠（2026-08-07）

一目均衡表を重ねた画面（S3-2）で、**転換線と基準線が乖離している足**にカーソルを合わせて検算した。カーソル位置 2026/08/07 00:35:

```
転換線[9]  = 158.332
基準線[26] = 158.140

候補A（スパンA = 転換線）           → 158.332
候補B（スパンA = (転換線+基準線)/2） → (158.332 + 158.140) / 2 = 158.236

実測 スパンA[9] = 158.236            → 候補B と小数第3位まで一致
```

同じ画面で `先行スパンA[26] 157.889` ≠ `スパンA[9] 158.236`、遅行線は両者とも 158.444 で一致。

> 注意: 転換線と基準線が同値になる足では両候補が同じ値になり判別できない。最初に撮った 2026/08/06 23:10 の足がこれに該当した（両方 158.040）。同種の検算を行うときは**2本が乖離している足を選ぶ**こと。

### 1.3 先行表示は行わない（重要）

**スパンA・スパンB を未来方向へずらさない。** 一目均衡表の雲は 26 本先行させて描くが、スパンモデルは現在足の位置に描く。

根拠3点:

1. S3 の設定画面に**先行本数のパラメータが存在しない**。
2. S2 p18 の図（5分足スパンモデル＋ボリンジャーバンド）を画素解析したところ、青・赤スパンの右端 x 座標が**ボリンジャーバンドの右端と完全に一致**した。ボリンジャーバンドは構造上ずらせないため、青・赤スパンもずれていないことになる。26 本先行していれば約 416px の差が出るはずだが、それが無い。
3. S3-2 で一目均衡表と同時表示したところ、**同じ足で値が違う**（`先行スパンA[26] 157.889` vs `スパンA[9] 158.236`、`先行スパンB[52] 157.879` vs `スパンB[52] 158.140`）。計算式が同じで値が違う以上、片方がシフトされている。チャート右端でも、最終足 12:40 に対し一目の雲だけが約26本ぶん先まで伸び、スパンモデルの帯は最終足で止まっていた。

同じ解析で、遅行線の終端が最終足より約 26〜28 本手前で切れていることも確認した（S2 p17 の「26遅行スパン」と整合）。

### 1.4 雲の色分け

```
スパンA > スパンB  → 雲色1（青）= サポートゾーン
スパンB > スパンA  → 雲色2（赤）= レジスタンスゾーン
```

## 2. スーパーボリンジャー

### 2.1 パラメータ（S3 の初期値）

| 要素 | 期間 | 既定色 | 備考 |
|---|---|---|---|
| TP（センターライン） | 21 | 青 | |
| σ1 | — | 緑 | |
| σ2 | — | 赤 | |
| σ3 | — | 水色 | |
| 遅行線 | **21** | マゼンタ | スパンモデルの 26 とは**別の値** |
| σ塗りつぶし | — | — | 既定 OFF |

### 2.2 計算

```
TP    = 21 期間の移動平均
σn上  = TP + n × σ
σn下  = TP − n × σ
遅行線 = Close を 21 本前へずらして描画
```

S3 の表示値で構造を検算した（USDJPY, 2026-08-07 時点のある足）:

```
TP[21] 157.694
σ1     157.730 / 157.658   → 上下とも ±0.036
σ2     157.766 / (下は未読) → 157.766 − 157.694 = 0.072 = 2 × 0.036
```

標準的なボリンジャーバンドの構造で矛盾しない。

**未確定な細部**（N4 の目視確認で詰める）:

- TP の基準価格が**終値**か**Typical Price (H+L+C)/3** か。ラベルが `TP` である点が引っかかるが、値が価格として表示されているので「TP＝センターラインの名称」の可能性が高い
- 移動平均の種別（SMA と仮定）
- σ が標本標準偏差か母標準偏差か（MT5 の `iBands()` は母標準偏差）

### 2.3 統合表示時のルール（S2 p17）

スパンモデルの上にスーパーボリンジャーを重ねる場合:

- スーパーボリンジャーは **±1σ と ±2σ のみ**表示（σ3 は出さない）
- 遅行線は**スパンモデルの 26 遅行スパンだけ**を表示（スーパーボリンジャーの 21 遅行線は出さない）

## 3. MT5 実装時の対応関係

| 本書の要素 | MT5 での取得 |
|---|---|
| スパンA / スパンB | **`iHighest` / `iLowest` から自前算出**（下記の理由により `iIchimoku()` は使わない） |
| 遅行線 | `Close[i+26]` との比較で判定（描画は `Close` を 26 本前へずらす） |
| TP / σ | `iBands(period=21)` |

> **スパンA・スパンB に `iIchimoku()` を使わないこと。** `iIchimoku()` の先行スパンのバッファは**すでに 26 本先行させた状態**で格納されており、現在足の位置にある値は 26 本前のデータから計算されたものになる。本指標が必要とするのは「現在のデータから計算した、先行させない値」で、それはバッファ上では 26 本**未来**の位置に当たるため `CopyBuffer` では取り出せない。高値・安値から直接計算すれば式は3行で済み、この落とし穴を丸ごと回避できる。

```
tenkan  = (Highest(High,  9, i) + Lowest(Low,  9, i)) / 2
kijun   = (Highest(High, 26, i) + Lowest(Low, 26, i)) / 2
spanA   = (tenkan + kijun) / 2
spanB   = (Highest(High, 52, i) + Lowest(Low, 52, i)) / 2
```
