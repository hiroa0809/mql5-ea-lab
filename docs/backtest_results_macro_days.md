# マクロ反応日での絞り込み — 検証結果

## 0. この文書の数字の出どころ

**本文の数字はすべて `tools/analyze-macro-days.py` の出力**。手で書き写していない。

```
rtk python tools/analyze-macro-days.py
```

各節の見出しに、スクリプトの何節から取ったかを書いてある。元データは総当たりの CSV（`%APPDATA%\MetaQuotes\Terminal\Common\Files\`）で、Git 管理外。作り直すときは:

```
tools/run-backtest.ps1 -LagMode 0 -UseClosePos false -SlopeMode 0 -Tag m2base_<TF> -Period <TF> `
  -From 2018.11.01 -To 2022.12.31 -Optimize -SqueezeUse 0 -EntryTrigger 0 `
  -EntryDelay 1:1:2 -ExitDelay 1:1:2 -MacroUse 0:1:2

tools/run-backtest.ps1 -LagMode 0 -UseClosePos false -SlopeMode 0 -Tag m2sqz_<TF> -Period <TF> `
  -From 2018.11.01 -To 2022.12.31 -Optimize -EntryTrigger 0:1:2 -SqueezeUse 1:1:5 `
  -SqueezeTF 0:1:3 -SqueezeLookback 6:60:126 -EntryDelay 1:1:2 -ExitDelay 1:1:2 -MacroUse 0:1:2
```

**`-LagMode 0 -UseClosePos false -SlopeMode 0` を必ず付ける。** 省くとスクリプトの既定値（3つとも「使う」側）で走り、P3 第1段階と比べられない別の実験になる。実際に使われた値は CSV の `lag_mode` / `use_close_pos` / `slope_mode` 列で確認する（スクリプト §0）。今回はすべて 0/0/0。

## 1. 何を試したか

別プロジェクト（OLS-MeanReversion_MT5）が「行き過ぎからの回帰」を狙う売買で**建てるのを止める日**として使っている一覧を、向きを逆にして借りた。マクロが荒れている＝回帰が効かない＝順張りには都合がよい、という仮説。

| 項目 | 内容 |
|---|---|
| 銘柄 / 期間 | USDJPY# ／ 2018-11-01 〜 2022-12-31（学習期間） |
| 時間足 | 10分・15分・1時間 |
| ティックの作り方 | 始値のみ（Model=2） |
| ロット | 0.10 固定（1 pip = 100円） |
| スパンモデル側 | 雲の色の変化だけ。②③④はすべて使わない（P3 第1段階と同じ） |
| 絞り込み | なし / 反応した日だけ / **反応しなかった日だけ（対照）** |
| 通り数 | 膠着なし12通り ／ 膠着あり2,052通り（1時間足は1,512通り） |
| 日付の一覧 | `docs/suppress_days_r2_report.txt`（73区間・実日数876日） |
| R2 の中身 | 恐怖指数25超 ∨ 恐怖指数が252日で+1.5σ超 ∨ 原油66日で−1.5σ未満 ∨ 信用代理66日で−1.5σ未満 |

## 2. 結論

**一律の効果は無い。ただし1つの組み合わせが学習期間の中では強く、学習期間だけでは決着しない。**

- 全パターンをまたいで見ると、**3つの時間足で向きがそろった関係は1つも無い**（§3）
- 一方、**15分足・③ケルトナー／4時間足・引き金「どちらでも」**では、取引299回・2022年に依存せず・合格ライン超え（§4・§5）
- **その組み合わせは10分足では逆を向く**（§4）

## 3. 全体像 — 一律には効かない

## 4. 候補 — 15分足・③ケルトナー／4時間足

スクリプト §4。同じ膠着設定で、引き金とマクロ絞り込みだけを変えたもの（入遅2・決遅2）。

| 時間足 | 引き金 | 絞込なし | **反応日のみ** | 反応なし日のみ |
|---|---|---|---|---|
| **15分** | **どちらでも** | 1.912（733回） | **4.356（299回）** | 0.229（434回） |
| 15分 | 膠着の開始 | 4.788（167回） | 8.027（62回） | 2.875（105回） |
| 1時間 | どちらでも | 5.268（373回） | 11.204（153回） | 0.936（223回） |
| **10分** | **どちらでも** | 0.418（1,032回） | **−0.131（436回）** | 0.819（596回） |
| 10分 | 膠着の開始 | 4.621（168回） | 4.846（63回） | 4.486（105回） |

**15分足・どちらでも**が最も条件が良い。取引299回あり、順序が単調（反応日 > 絞込なし > 反応なし日）で、執行4通り（1/1・2/1・2/2）すべてで 4.28〜4.37 pips に収まる。合格ライン相当（ネット 3.01 pips）を超える。

**10分足では逆を向く。** 反応日のみが −0.131 で、絞り込みなし（0.418）より悪い。膠着の開始では3者にほぼ差が無い（4.62 / 4.85 / 4.49）。

## 5. 2022年への依存 — この候補には無い

スクリプト §5。15分足・③ケルトナー／4時間足・入遅2決遅2 の年別。

**引き金「どちらでも」**

| 年 | 絞込なし | **反応日のみ** | 反応なし日のみ |
|---|---|---|---|
| 2018 | 8,480 (25回) | 8,480 (25回) | — |
| 2019 | −22,410 (233回) | **−6,780 (28回)** | −15,630 (205回) |
| 2020 | 100,360 (192回) | **73,040 (125回)** | 27,320 (67回) |
| 2021 | −8,060 (141回) | **15,970 (24回)** | −24,030 (117回) |
| 2022 | 61,800 (142回) | **39,530 (97回)** | 22,270 (45回) |

| | 合計 | 2022年の割合 | **2022年を除くと** |
|---|---|---|---|
| 絞込なし | 140,170円 / 733回 / 1.912 pips | 44% | 78,370円 / 591回 / **1.326 pips** |
| **反応日のみ** | 130,240円 / 299回 / 4.356 pips | **30%** | 90,710円 / 202回 / **4.491 pips** |
| 反応なし日のみ | 9,930円 / 434回 / 0.229 pips | 224% | −12,340円 / 389回 / **−0.317 pips** |

**2022年を除くと成績が上がる**（4.356 → 4.491）。他の候補（1時間足全般、引き金「膠着の開始」）が2022年に依存するのと性質が違う。2021年は絞り込みなしが赤字（−8,060）なのに反応日のみは黒字（+15,970）。

弱点は **2019年が赤字**（−6,780・28回）であること。

## 6. 取引数の信頼度

スクリプト §6。「反応日のみ」の全パターン分布。

| 時間足 | 取引数中央値 | 100回未満の割合 | 1取引pips 四分位範囲 |
|---|---|---|---|
| 10分 | 319 | 14% | −1.95 〜 0.60 |
| 15分 | 231 | 20% | −0.89 〜 2.04 |
| **1時間** | **65** | **62%** | **2.99 〜 12.55** |

**1時間足の大きな数字は採らない。** ばらつきの幅が往復コストと桁違いで、1取引 12 pips という水準自体が実現しない。§4 の候補を15分足で取ったのはこのため。

## 7. 未決 — 学習期間では決着しない

§4・§5 の候補は**2,052通りの中から選んだ組み合わせ**である。③ケルトナー／4時間足は P3 で先に選ばれていたが、引き金「どちらでも」はここで選んだ。**選んだ本人のデータで良く見えるのは当然**なので、これだけでは採否を決められない。

決着させるなら**検証用期間（2023/01〜2024/10・残り2〜3回）**を1回使うことになる。使う前に確認すべきこと:

- **2023年の対象日は21日しかない**。検証用期間で何取引になるかを先に見積もる。取引が数十回では学習期間と同じ問題を繰り返す
- **単純な変動幅フィルタとの比較**（マクロ指標が「動きの大きい時期」を選んでいるだけではないかの切り分け）は未実施

## 8. 実装

判定は `Include\Signals\MacroDays.mqh`、EA の入力は「マクロ反応日での絞り込み」。**既定は「使わない」**。総当たりの CSV には `macro_use` 列が残る。

元の一覧は UTC のカレンダー日だが、判定は足の時刻（サーバー時刻・UTC+2〜3）で行うため、区間の境目が数時間ずれる。
