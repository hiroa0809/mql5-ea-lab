# エントリーシグナル仕様

本プロジェクトで採用するエントリー用オシレータ部品 3 種の仕様。

> **本書の範囲**: エントリーシグナルの生成と、それが検証された前提条件（§1.2）。
> **決済ルールは「N24＝24 本後のタイムストップ」で確定済み**である（前プロジェクトの IS/OOS 由来）。利確・損切りの追加是非のみ未確定（§5）。
> 現行 `CSignalRSI::ShouldExit()` の RSI 50 クロス決済は**検証されていない仮置き**であり、これを使うと優位性が失われる（§5 に実測を記録）。

---

## 1. 共通ルール

3 部品はすべて**同一の売買ルール**に従う。差異は「どの計算式で行き過ぎを測るか」だけである。

| 項目 | 内容 |
|---|---|
| 思想 | 逆張り（平均回帰）。行き過ぎたら戻る方に賭ける |
| エントリー | シグナル発生の**次の足の始値**で成行 |
| 判定タイミング | 確定足のみ（未確定足では判定しない） |

### 1.1 即エントリー規約（クロス判定）

```
指標が「売られすぎゾーン」に突入した瞬間 → 買い（Long）
指標が「買われすぎゾーン」に突入した瞬間 → 売り（Short）
```

シグナルは**クロス**（外から中への突入）でのみ発火する。

- **ゾーン滞在中は発火しない**。外から中へ入った、その 1 本だけがシグナル。
- これにより同一局面での重複エントリーを防ぐ。
- 「ゾーンから戻るのを確認してから入る」確認型ではなく、**突入と同時に入る先回り型**を全指標で採用する。

判定式:

```
prev >= lower_threshold  AND  curr <  lower_threshold  → Long
prev <= upper_threshold  AND  curr >  upper_threshold  → Short
```

**境界（値が閾値ちょうど）の扱いは研究側 `band_entry_signal` に厳密に合わせる**こと。すなわち `prev` が閾値ちょうどなら「まだ外側」、`curr` は閾値を厳密に越えて初めて「突入」とみなす。等号を逆に付けると検証時と判定が変わる（2026-08-02 に EA 側の実装が逆になっていたのを訂正）。

`prev` / `curr` のいずれかが無効値（NaN）の場合、比較は両方 false となりシグナルは発火しない。

## 2. 採用部品

### 2.1 CCI(14) ±200

> **閾値は ±100 から ±200 へ変更済み（2026-07-27）**。スプレッド前提を実勢（3.4 pips）へ見直した結果、±100 はグロス予算 4.30 pips に対し余裕が 1 pips 未満となり**採用取消**。±200 に差し替えた。

**CCI = Commodity Channel Index（商品チャネル指数）**

直近 14 本の平均から現在価格がどれだけ離れているかを測る。上下限のない指標。

#### 計算

```
TP  = (高値 + 安値 + 終値) ÷ 3        ← その足の代表価格
SMA = TP の直近14本の平均
MD  = TP の SMA からの平均絶対偏差
CCI = (TP − SMA) ÷ (0.015 × MD)
```

定数 `0.015` は「通常の値動きなら CCI が ±100 に収まる」ように調整するための係数。すなわち ±100 が一般的な「行き過ぎ」の目安である。**本プロジェクトはさらに外側の ±200 を採用する**（±100 では発生頻度が高すぎ、1 トレードあたりの値幅がスプレッドを吸収できないため。§2.1 冒頭）。

#### 売買ルール

| 条件 | 意味 | アクション |
|---|---|---|
| CCI が **−200 を下抜け** | 平均より下に行き過ぎた | **買い** |
| CCI が **+200 を上抜け** | 平均より上に行き過ぎた | **売り** |

#### 実装上の注意：MD=0 の扱い（既知の無害な差分）

研究側の実装では MD=0（直近 14 本の TP が完全に不動）のとき CCI を **NaN**（シグナル無し）として扱っている。0 を返すと以下の偽クロスが発生するためである。

```
CCI: −150 → (MD=0 で 0) → −150
     ゾーン内   中央値      ゾーン内
                ↑ ここで「外から中へ入った」と誤認され、
                  次の足で偽の Long シグナルが出る
```

実際には価格は −150 のゾーンに居続けただけであり、「ゾーン滞在中は発火しない」という設計意図が壊れる。NaN であれば両比較が false となり抑止される。

**ただし EA 実装では MQL5 標準の `iCCI()` をそのまま使用してよい。**

- 標準実装は MD=0 時にゼロ除算ガードで 0.0 を返すとみられ、上記 NaN 方式と挙動が異なる。
- しかし研究側の実データ検証で **MD=0 は 1 件も発生しなかった**（5 銘柄 × 2 時間足 × 期間 {14, 20}、15m 約 226 万ウィンドウ・1h 約 46 万ウィンドウ、計約 272 万ウィンドウで 0 件）。
- MD=0 は「直近 14 本の TP が 1 ティックも動かない」状態を意味し、FX の 15 分足では現実的に発生しない（発生するとすればデータ欠損や凍結クォートの人工物）。
- したがって NaN / 0 の差はバックテスト結果に影響しない。ガードを追加しても実質的に一度も発火しないため、**本差異は「既知の無害な差分」として記録し、EA 側にガードを設けない**方針とする。

補足: NaN 方式には「NaN が出た足では `prev` も NaN になるためシグナルが 2 本分抑止される」（0 方式なら 1 本のみ）という副作用があるが、これも MD=0 が発生しない以上は顕在化しない。

### 2.2 CMO(14) ±50

**CMO = Chande Momentum Oscillator（シャンデ・モメンタム・オシレーター）**

直近 14 本で上昇量と下落量のどちらが優勢かを −100〜+100 で表す。

#### 計算

```
SU  = 直近14本の「上昇幅」の合計
SD  = 直近14本の「下落幅」の合計
CMO = 100 × (SU − SD) ÷ (SU + SD)
```

| 状態 | CMO |
|---|---|
| 14 本すべて上昇（SD=0） | **+100** |
| 14 本すべて下落（SU=0） | **−100** |
| 上下が拮抗 | **0** |

RSI と発想は近いが、**RSI が平滑化するのに対し CMO は単純合計**であるため、より鋭く素直に振れる。

#### 売買ルール

| 条件 | 意味 | アクション |
|---|---|---|
| CMO が **−50 を下抜け** | 下落が明確に優勢に傾いた | **買い** |
| CMO が **+50 を上抜け** | 上昇が明確に優勢に傾いた | **売り** |

#### 実装上の注意

- **MQL5 に標準の CMO 関数はないため自前実装が必要**。
- `SU + SD = 0`（直近 14 本が完全に不動）のゼロ除算ケースは、CCI の MD=0 と同種である。自前実装であるため、**NaN（シグナル無し）を返す**方式で実装する。

### 2.3 RSI(9) 30 / 70

**RSI = Relative Strength Index（相対力指数）**。最も一般的な逆張り指標。

#### 計算（Wilder 方式）

```
平均上昇幅 / 平均下落幅 を指数平滑（EMA, alpha = 1/9）で算出
RS  = 平均上昇幅 ÷ 平均下落幅
RSI = 100 − 100 ÷ (1 + RS)
```

値域は 0〜100。一般的には期間 14 が用いられるが、本プロジェクトでは **9（短め＝反応が速い）** を採用する。

#### 売買ルール

| 条件 | 意味 | アクション |
|---|---|---|
| RSI が **30 を下抜け** | 売られすぎゾーンに突入 | **買い** |
| RSI が **70 を上抜け** | 買われすぎゾーンに突入 | **売り** |

#### 実装上の注意

MQL5 標準の `iRSI()` は Wilder 方式であり、そのまま使用してよい。

## 3. 3 部品の比較

| 部品 | 計算のベース | 値域 | グロス予算 | 取引数 (IS / OOS) | OOS 純期待値 | 性格 |
|---|---|:--:|:--:|:--:|:--:|---|
| **CCI(14) ±200** | 価格の平均からの乖離 | なし | 4.30 pips | 12,383 / 9,386 | 3.73 pips | 高頻度・薄利 |
| **CMO(14) ±50** | 上昇量 vs 下落量（単純） | ±100 | 6.82 pips | 4,318 / 3,410 | 3.44 pips | 低頻度・厚利 |
| **RSI(9) 30/70** | 上昇量 vs 下落量（平滑） | 0〜100 | 5.06 pips | 6,019 / 4,573 | 2.48 pips | バランス |

> グロス予算・取引数・純期待値は**すべて §1.2 の採用構成（15 分足・N24）での測定値**である。これらの列は引き継ぎ時に一度失われており、決済ルールが N24 であることを復元する唯一の手掛かりだった。**削除しないこと。**

3 部品はいずれも「行き過ぎたら戻る」という同一の思想に立つが、**測り方が異なるためシグナルの出るタイミングがずれる**（指標間の相関は検証済み）。これが複数を部品として保持する理由である。

## 4. 実装形態

共通インターフェースを持つ `.mqh` 部品群として実装し、EA 本体が部品を差し替える構成とする。今後エグジット部品を追加する際の組み合わせを容易にするためである。

```
Include/
  Signals/
    ISignal.mqh      // 共通インターフェース
    SignalCCI.mqh
    SignalCMO.mqh
    SignalRSI.mqh
Experts/
  EaLab.mq5          // 部品を選択して駆動
```

各部品は共通インターフェースを通じて、確定足ごとに Long / Short / なし のいずれかを返す。クロス判定（1.1 節）は部品側に持たせ、EA 本体は方向のみを受け取る。

## 5. 決済ルールの状態

### 確定している部分

**N24（エントリーから 24 本後に無条件決済）が検証済みの決済ルール**である（§1.2）。前プロジェクトの IS/OOS は N=[3, 6, 12, 24] を総当たりし、N=12 / N=24 が採用、**N=3 / N=6 は不採用（マイナス）**だった。短すぎても長すぎても優位性が消える。

### 未確定の部分

- **利確・損切りの追加是非**: N24 のタイムストップのみで損切りは無い。追加すべきかは未検証。
- エグジット部品としての実装形態（`ISignal` から分離するか）。

### 実装状況

**2026-08-02 に N 本タイムストップを実装し、仮置き決済を撤去した。**

- `ISignal` から `ShouldExit()` を**削除**した。決済は 3 部品に共通のため部品側に持たせない。未検証の仮置きがコードに残っていると誤って再有効化されるため、インターフェースごと消している。
- 決済は `EaLab.mq5` の `CloseExpiredPositions()` が担当する。`iBarShift(POSITION_TIME)` で保有**本数**を数え、`InpExitBars`（既定 24）に達した足で成行決済する。**経過時間ではなく足数**で数えるため、週末やギャップで足が飛んでも本数は狂わない（研究側 `forward_return.py` の `exit_pos = entry_pos + N` と同じ）。
- `InpAllowOverlap`（既定 true）で**重複保有の可否を切り替えられる**。研究側は保有中かどうかを見ずシグナルごとに独立してトレードを数えるため、条件を揃えるには重複を許す必要がある（§1.2 の検証再現時は true）。運用時にどちらが優れるかは未検証のため、OFF も選べる形にしてある。重複保有はヘッジ口座が前提で、ネッティング口座では `OnInit` が起動を拒否する。

### 参考: 撤去前の仮置き決済がどれだけ悪かったか（2026-08-02 実測）

削除済みの **RSI 50 クロス決済**（時間上限なし・損切りなし）で回したバックテスト（15 分足・4.3 年・3,353 トレード）:

| | 結果 |
|---|---|
| 総損益 | **-1,227 USD**（PF 0.359 / 勝率 42.7%） |
| 1 トレードあたり | **-24 pips**（うちスプレッドは約 3 pips のみ） |
| 保有 12 本以内のトレード合計 | **+22,923 pips** |
| 保有 24 本超のトレード合計 | **-66,434 pips（損失全体の 83%）** |
| 平均保有 | 勝ち 8.4 本 / 負け 24.3 本（**負けが 2.9 倍**） |

原因は決済条件の非対称性である。RSI 50 クロスには**時間上限が無い**ため、勝ちは RSI がすぐ戻って早く閉じ、負けは RSI が 50 に戻るまで持ち続ける（最長 206 本＝51.5 時間、最大損失 -890 pips）。N24 はこれを 24 本で切る。

### 次にやること: 研究との一致確認

N24 実装後のバックテストで、研究の値を再現できるかを確認する。**再現できるまで採用可否の判断には使わない。**

| 比較指標 | 研究の IS 値（RSI9 30/70・15m・N24） | 判定 |
|---|---|---|
| トレード数 | 6,019 | ±15% 以内 |
| **グロス期待値/トレード** | **+5.061 pips** | **±20% 以内（本命）** |

- 比較期間は **2018.09.27〜2022.12.31**（研究の IS 実効期間と一致）。`InpAllowOverlap=true` で回す。
- **ネットではなくグロスで比べる**。研究は固定スプレッド（2.795 pips）を一律控除しているのに対し、テスターは実ティックの可変スプレッドを使うため、ネットのままだと差がロジック由来かコスト由来か分離できない。テスターのレポートからは、約定明細の 1 トレードあたり pips に当該期間の実測スプレッド（2.2〜2.6 pips）を足し戻してグロスを復元する。
- データソースが異なる（研究は自前 DB / テスターは XM 配信）ため**完全一致はしない**。足の並びも週境界も揃わない。
