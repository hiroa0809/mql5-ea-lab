# 売買ルール要件定義 — スパンモデル / スーパーボリンジャー

> 対象: `docs/indicator_spec.md` で定義を確定した2指標を使った売買ルール。
> 本書は**「if 文にそのまま落とせる粒度」まで一意化すること**を目的とする。計算定義は扱わない（`indicator_spec.md` を参照）。
> 作成 2026-08-07（N1b）。

## 0. 本書の読み方

資料（S1/S2）は裁量トレードの解説であり、機械的なルールになっていない。本書は資料の記述を次の3種類に分けて扱う:

| 記号 | 意味 |
|---|---|
| **【資料】** | 出典に明記されている。変更する場合は根拠が要る |
| **【一意化】** | 資料が曖昧なため Claude が定義を決めた。**候補が複数あった箇所であり、変えてよい** |
| **【不採用】** | 資料にあるが初版では実装しない。理由を併記 |

**【一意化】の箇所は input で切り替えられるようにする。** 負けたときに「ルールが悪いのか一意化の仕方が悪いのか」を切り分けるため。

出典の対応: S1 = ヒロセ通商テクニカル分析 #26、S2 = 「勝つための方程式 スペシャル」PDF（頁番号付き）。

## 1. 資料が言っていること（抽出結果）

### 1.1 戦略の骨格（S2 p2, p3）

- **マルチタイムフレーム**: 60分足スーパーボリンジャーで全体観 → 5分足/1分足スパンモデルで売買ポイント（p2）
- 大局観の方向へのポジションは積極的、逆方向は慎重（p2）
- **トレンド判断はスーパーボリンジャーが担当**（p3）
- **スパンモデルの売買シグナルは、トレンド相場では「順指標」、レンジ相場では「逆指標」**（p3）

### 1.2 スーパーボリンジャー: トレンド開始（S2 p11）— 4条件の AND

| # | 上昇トレンド開始 | 下降トレンド開始 |
|---|---|---|
| 1 | 直前が膠着・レンジ（バンド幅収束） | 同左 |
| 2 | 遅行スパン**陽転** | 遅行スパン**陰転** |
| 3 | 実勢ローソク足**終値**が **+1σ を上回る** | 実勢ローソク足**終値**が **−1σ を下回る** |
| 4 | バンド幅が**拡大** | 同左 |

### 1.3 スーパーボリンジャー: 調整局面入り／ターゲット（S2 p13）

- 上昇相場 → 反落へ入るサイン: 終値が **+1σ を下回る**、バンド幅が収束傾向、遅行スパンがローソク足に**絡む**
- 下降相場 → 反騰へ入るサイン: 終値が **−1σ を上回る**、同上
- **調整局面のターゲット価格**: 反落 = センターライン〜−2σ ／ 反騰 = センターライン〜+2σ

### 1.4 スーパーボリンジャー: レンジ相場（S2 p15）

- 値幅の大きいレンジ: 終値が **±2σ の間**で推移＋バンド幅縮小/フラット＋遅行スパンが絡む
- 値幅の小さいレンジ: 終値が **±1σ の間**で推移＋同上

### 1.5 スーパーボリンジャー: その他（S1）

1. 移動平均が低下＋バンド拡大＋終値が移動平均を下回る → 売りシグナル・下落トレンド
2. **−1σ 〜 −2σ の間で推移 = 「巡航速度」の下落トレンド（理想的）**
3. 終値が −1σ を上抜け → 下落トレンドの後退
4. 移動平均が下落→横ばいとなる過程で終値が移動平均を上回る → トレンド転換の確認
5. 遅行スパンがローソク足を上抜け = 買い / 下抜け = 売り

### 1.6 スパンモデル: 判断方法（S2 p5, S1）

| # | 要素 | 内容 |
|---|---|---|
| 1 | 赤色スパン（長期・スパンB） | **傾き**で判断 |
| 2 | 遅行スパン（中期） | 陽転・陰転、ローソク足との位置関係 |
| 3 | 青色スパン（短期・スパンA） | 実勢ローソク足との位置関係 |
| 4 | 売買シグナル | サポートゾーン（青ゾーン）＝買い / レジスタンスゾーン（赤ゾーン）＝売り |

S1 の補足:
- **スパンA > スパンB = 買いシグナル**、スパンB > スパンA = 売りシグナル
- シグナル点灯中にローソク足がスパンA へ接近 → 押し目買い／戻り売りを示唆
- ローソク足が雲の中 = 勢いが弱まっている

### 1.7 統合表示（S2 p17）

- スパンモデル上にスーパーボリンジャーを重ね、**±1σ と ±2σ のみ**表示。遅行線はスパンモデルの26のみ
- 目的は**利食いの判断**と、レンジ相場での売り／買いレベルの目途

## 2. 全ルール共通の前提

### 2.1 判定タイミング — 確定足のみ 【一意化】

**すべての判定は確定足（`shift = 1`）で行い、ザラ場（ティック）判定はしない。**

- 根拠: 資料の条件はほぼ全てが「終値」ベース（p11-③、p13、S1-1/3/4）。σ・TP も終値から算出する
- ザラ場判定を混ぜると、同じ足の中で成立・不成立が揺れて再現性が落ちる
- エントリーは判定が成立した**次の足の始値で成行**。逆指値エントリー（旧 `EaPriceAction.mq5` の資産）は初版では使わない

### 2.2 銘柄・時間足

- **`USDJPY#` / M5 を主軸、M15 を比較対象**（2026-08-07 の暫定決定。TASK_MASTER に経緯）
- 統合ルール（R3）のみ上位足 H1 を併用
- **銘柄・時間足は EA の設定項目にせず、貼り付けたチャート（バックテストではテスターの指定）に従う**（2026-08-08 決定）。設定の出どころを1つにして、テスターの指定と EA 側の設定が無言で食い違う事故を防ぐ。R3 の上位足だけは設定項目で持つ

### 2.3 検証の順序 — 単体 → 統合

`docs/backtest_design.md` と TASK_MASTER の実装方針に従い、**片方ずつ IS にかける**。

| ID | ルール | 使う指標 | 時間足 |
|---|---|---|---|
| **R1** | スーパーボリンジャーのトレンド開始（p11） | SB のみ | 単一（M5 / M15） |
| **R2** | スパンモデルの雲転換・順張り（p5, S1） | SM のみ | 単一（M5 / M15） |
| **R3** | 統合（上位足 SB で方向 → 下位足 SM でタイミング） | 両方 | H1 + M5 |

**R3 は R1 / R2 の結果を見てから着手する。** 資料の本来の戦略は R3 だが、単体の成績が分からないまま統合すると、負けたときに切り分けられない（前回の失敗パターン）。

## 3. 用語の一意化（最重要）

資料の語のうち、**そのままでは if に落ちないもの**を定義する。すべて【一意化】。

記号: `L` = 遅行線の本数（SM は 26、SB は 21）。`i` は判定対象の足のシフト（既定 1 = 確定足）。

### 3.1 遅行スパンの「陽転／陰転／絡む」

遅行線は `Close[i]` を `i+L` の位置に描く。線の右端から判定足の手前までの足と比べる。

```text
LagAbove(i) := Close[i] > max( High[i+1] … High[i+L] )   // 陽転
LagBelow(i) := Close[i] < min( Low [i+1] … Low [i+L] )   // 陰転
LagInside(i):= どちらでもない                            // 「絡む」
```

- **判定足そのものは含めない。** 自分の高値は終値より必ず上なので、含めると絶対に成立しない
- **足全体（高値・安値）と比較する厳格版のみ。** S1 の「ローソク足を上抜けていれば」は実体ではなく足を指す文言。緩い版（終値どうしの比較）は結果が「上」「下」の2つになり、**中間状態の「絡む」が作れない**。「絡む」は p13（調整局面入り）と p15（レンジ）が使う状態
- **比較先を `High[i+L]` の1本だけにしない**（2026-08-09）。1本だと単独成立率が 86.5% あり、R1 の③（§3.3）が成立したときは **100% 成立**して条件として働かない。直近 L 本に変えると単独 13.6%、③と重なるのは 41.0%（人工データ30万本での実測）
- **R2（スパンモデル）の②は N5-2 で決める。** 上の重複は R1 の③に対する測定であり、引き金が雲の転換である R2 には当てはまらない

### 3.2 バンド幅の「拡大」

```text
BW(i) := σ1上(i) − σ1下(i)   ( = 2σ(i) )
```

σ そのものを使っても同値だが、資料の語に合わせて BW で書く。

**拡大**（p11-④）:
```text
BWExpanding(i) := BW(i) > BW(i + InpBWExpandLookback)     // 既定 3
```
1本前との比較（`> BW(i+1)`）だけだと1本のノイズで成立してしまうため、既定は3本前と比べる。`1` にすれば資料の素直な読みになる。

「収束」は §3.3 の膠着に置き換えた。バンド幅では測らない。

### 3.3 遅行スパンと帯の位置関係 — 「膠着」と「突破」

遅行線の右端は「今の終値を `L` 本前の位置へ置いた点」なので、その真下にある帯は **`L` 本前の時点で計算された帯**になる。この距離を σ 何個ぶんかで表す 【一意化】:

```text
LagZ(i) := ( Close[i] − センターライン(i+L) ) / σ(i+L)
           // σ(i+L) = 0 のときは 0 とする（値動きが無い＝内側扱い）
```

`LagZ` は「`L` 本かけて価格が正味どこへ行ったか」を、当時のσで割った量になる。

**膠着**（p11-①「直前が膠着、レンジ相場」）:
```text
Squeezed(i) := i+1 .. i+InpSqueezeBars のすべての足で  |LagZ| ≤ InpSigmaMult
               // 既定: InpSqueezeBars = 21、InpSigmaMult = 3.0
```

**突破**（p11-③ の置き換え・トレンド開始の引き金）— 遷移として扱う:
```text
LagBreakUp(i)   := LagZ(i) >  InpSigmaMult && LagZ(i+1) <=  InpSigmaMult
LagBreakDown(i) := LagZ(i) < −InpSigmaMult && LagZ(i+1) >= −InpSigmaMult
```

- **判定足そのものは膠着に含めない**（`i+1` から数える）。p11-① は「**直前が**膠着」であり、判定足では既に抜け始めている
- **①と③を同じ物差しにした**（2026-08-09）。「止まっていた遅行線が抜けた」という1つの出来事になり、遷移する条件が2つに割れて取引が発生しない失敗を避けられる
- **帯の幅では膠着を測らない。** 2026-08-08 版は「直前21本の終値が ±1σ の内側」（p15 のレンジ定義）だったが、**同じ21本から作った帯と自分を比べる形なので何も測っていなかった**。値動きの大きさを20倍にしても成立率は 45.7% で変わらず（人工データ30万本での実測）、21本連続は約15日に1回しか起きなかった。2026-08-07 版の平均比（21本／120本／0.80）も資料に根拠が無く、廃止済み
- 上の `LagZ` はレンジとトレンドを区別する。±3σ で内側にいる割合はレンジ 71.1% 対トレンド 34.6%、±1σ なら 29.1% 対 6.8%。**ただし値動きの大きさ（帯の細さ）は測っていない**。膠着明けで拾いたいのは「どこにも行っていなかった価格が動き出す」ことなので、これで足りる
- **①は input で ON/OFF できるようにする**。①が取引を止めている場合に外して確かめるため

### 3.3b 手仕舞いに使う「終値と ±1σ」

**調整局面入り（p13）は状態として扱う** 【一意化】:
```text
BelowSigma1Up(i) := Close[i] < σ1上(i)
AboveSigma1Dn(i) := Close[i] > σ1下(i)
```

p13 は保有中に毎足チェックする手仕舞い条件で、遷移を取り逃すと決済されないまま走り続ける。エントリー側（§3.3）が遷移なのと対になる。

### 3.4 スパンB（赤色スパン）の「傾き」（p5-1）

```text
SpanBUp(i)   := SpanB(i) > SpanB(i + InpSlopeBars)     // 既定 5
SpanBDown(i) := SpanB(i) < SpanB(i + InpSlopeBars)
// InpR2_SlopeAllowEqual = true なら >= / <= に切り替える
```
- **スパンB は 52 本の高値・安値の中値なので階段状**。52本の最高値か最安値が入れ替わるまで完全に平らで、レンジ相場では何十本も動かない。`>` のままだと平らな期間はすべて不成立になる
- 資料は「傾きで判断」（p5-1）と言うだけで、**本数も判定方法も書いていない。既定 5 に根拠は無い**。5 本は階段1段の間隔より短い可能性がある
- 既定は `>` のまま。**イコール許可を input で持ち**、条件④の成立回数を見てから調整する

### 3.5 雲の色（サポート／レジスタンスゾーン）

```text
CloudBlue(i) := SpanA(i) > SpanB(i)     // サポートゾーン ＝ 買いシグナル
CloudRed(i)  := SpanB(i) > SpanA(i)     // レジスタンスゾーン ＝ 売りシグナル
CloudFlip(i) := CloudBlue(i) && !CloudBlue(i+1)   // 青へ転換（買いトリガー）
```

## 4. R1: スーパーボリンジャー トレンド開始

### 4.1 エントリー 【資料】p11 ＋ 【一意化】トリガーの割り当て

4条件のうち**どれをトリガー（当足で新規成立）にするか**は資料に書かれていない。4つ全てを遷移にすると同一足で同時に起きることがほぼ無く、取引が発生しない。

→ **③（遅行スパンの帯突破）をトリガー、①②④は状態フィルタ**とする 【一意化】。

```text
買いエントリー（すべて AND、i = 1）:
  ① Squeezed(1)            // 遅行スパンが直前21本ぶん ±3σ の内側にとどまっていた
  ② LagAbove(1)            // 遅行線が直近21本の高値をすべて上回っている（状態）
  ③ LagBreakUp(1)          // 遅行スパンが +3σ を新規に上抜けた   ← トリガー
  ④ BWExpanding(1)         // バンド幅が拡大している

売りエントリー（すべて AND、i = 1）:
  ① Squeezed(1)
  ② LagBelow(1)
  ③ LagBreakDown(1)        ← トリガー
  ④ BWExpanding(1)
```

- **p11-③（終値が ±1σ を上回る）は落とした**（2026-08-09）。遷移する条件を2つ持つと同じ足で揃わず取引が発生しない。①と同じ物差しで測る③のほうを残した
- 発注は次足始値で成行（§2.1）

### 4.2 決済 【資料】p13 ＋ 【一意化】損切り

```text
買いの手仕舞い（いずれか先に成立したもの）:
  X1 利確/撤退: Close[1] < σ1上(1)                    ← p13「調整の反落局面へ入るサイン」
  X2 損切り  : Bid ≤ EntryPrice − InpSLSigma × σ_entry  （**既定 OFF**。InpSLSigma = 2.0）
  X3 タイムストップ: 保有 InpHoldBars 本経過（既定 OFF）

売りの X1・X3 は上下反転。**X2 だけは反転ではない**:
  売りの損切り: Ask ≥ EntryPrice + InpSLSigma × σ_entry   ← Bid ではない
  （買い建玉は売って閉じるので Bid、売り建玉は買って閉じるので Ask を見る）
```

**X1 を p13 の3条件 AND にしない理由** 【一意化】: p13 は「バンド幅が収束傾向」「遅行スパンが絡む」も併記するが、3つ揃うのを待つと調整が進んだ後の決済になり、突破で得た含み益を吐き出す。**手仕舞いは早い側に倒す**。

**X1 は3方式から選べるようにした** 【一意化】（2026-08-09）。input `InpR1_Exit` で切り替え、**学習期間で3つとも走らせて並べる**（回数制限が無いため追加コストが無い）。判定は 3.7 pips のまま動かさない。

| | 定義 | 人工データでの保有中央値 |
|---|---|---|
| **A**（既定・【資料】p13） | `Close[1] < σ1上(1)` | 6本 |
| **B** 【一意化】 | `LagZ(1) ≤ 1.0`（§3.3） | 23本 |
| **C** 【一意化】 | `LagZ(1) < 0`（反対側へ陰転） | 31本 |

- **A は他の2つと性質が違う。** エントリーは④で「バンド幅が拡大している」ことを要求するので、**発火を起こした値動きがそのまま今のσを膨らませる**。A は「今の帯」を基準にするため、エントリーの勢いが強いほど決済のハードルが下がる。B・C はエントリーと同じ物差し（`LagZ`）なのでこの反応が無い
- **B の 1σ は固定**。つまみにすると学習期間の成績が実力以上に出る
- **長く持つこと自体は優位性を生まない。** 人工データ（ランダムウォーク）では A/B/C とも獲得値幅の平均が 0σ 付近で差が無かった。差が出るかは実データの結果次第

**X2（損切り）は資料に記載が無い** 【一意化】。裁量前提の資料なので当然。**既定は OFF**（2026-08-08）— 手仕舞いは X1 かドテンで行うのが基本設計であり、損切りの有無はバックテストで比較して決める。調整できるつまみを増やすほど IS の成績は実力以上に良く出る。使う場合は**注文にサーバー側の損切り価格を付ける**（ティック監視が要らず §2.1 と整合し、建玉の向きに応じた気配も MT5 が自動で見る）。実装の詳細は `docs/implementation_design.md` §3。

- `σ_entry` は**建玉時の σ を固定**して使う（変動する σ で SL を動かすとトレーリングになり、別のルールになってしまう）
- σ 基準にした理由: 指標と単位が揃い、ボラティリティに自動追随する。ATR を別途持つ必要もない
- 既定 2.0σ の根拠: p13 の調整ターゲットが「センターライン〜−2σ」＝ +1σ で入った買いが −2σ まで行けば明確に前提が壊れている。**仮置きであり IS で調整する**

**X3 は既定 OFF**。R1 はトレンドフォローで、保有が伸びること自体は想定内。旧 `EaPriceAction.mq5` のタイムストップ実装を流用できるので、input だけ用意しておく。

| σ（USDJPY M5） | **未測定**（N4 のチャート表示時に確認） | 「約 16.7 pips」は 2026-08-08 に取り下げ。`indicator_spec.md` S3-3 の1本読みで、急騰局面と重なる窓だった。EA は σ を実行時に計算するため、**事前の実測値は不要** |
| **往復コスト（判定に使う値）** | **1.22 pips** | **2026-08-07 実測**。`USDJPY#` M5、**直近（2024/11〜2026/08）** の22ヶ月・5,876万ティック。中央値 0.90 / p90 1.20 / p99 1.90 / 最小 0.80。手数料 0.00。**IS 期間の値（0.69）は使わない**（下記「期間によるコストの変化」） |
| **必要なグロス期待値** | **約 3.7 pips / トレード** | 1.22 × 3。損益分岐点は ×1 で、×3 は安全マージン（下記） |
| レイテンシコスト | **無視できる（0.002 pips）** | 2026-08-07 実測。同一期間・同一銘柄で遅延なし（1.218）と遅延あり 241ms（1.220）を比較。方式A（遅延の影響を受けない対照群）が完全一致しており条件は揃っている |
| 勝ちトレードの想定値幅（グロス） | **未確定** | +1σ 突破 → +1σ 割れの往復。出入りとも**次足始値**であり、σ 自体も毎足動くため、**センターラインの移動分と一致するとは限らない**。IS の実測で確認する |
| 想定保有本数 | **10 〜 60 本（50分〜5時間）** | **未実測の仮説。IS の平均保有本数で必ず確認する** |

**判定式（コスト側は N0 で確定済み）**:
```text
3.7 pips  ≤  IS の「1トレードあたり平均グロス損益」
              ↑ 勝ちトレードも負けトレードも含めた全取引の平均（＝期待値）

満たさなければ実装せず条件を変える
```

**事前ゲートで言えるのは「前回型の事故は回避済み」まで。** 前回は往復 22 pips がグロス 5.06 pips を上回っており、値幅を知らずとも失格が分かる水準だった。今回の 1.22 pips はそうではない。**優位性の有無は IS でしか出ない**（判定式の右辺は R1 を実装しないと存在しない）。

> **右辺を実装前に見積もろうとしないこと。** 2026-08-07 に「3.7 pips は σ（16.7 pips）の 22% だから通過」と書いたが、この σ は1本読みで根拠が無かった。実装前に出せない数字を無理に埋めると、こうなる。

#### 期間によるコストの変化（2026-08-07 実測）— 判定に IS のコストを使わない理由

`USDJPY#` M5 の往復コストは**期間によって約1.8倍の差がある**。

| 期間 | 層 | 中央値 | 最小 | 方式B 平均 |
|---|---|---|---|---|
| 2018/11〜2022/12 | IS | 0.60 | 0.60 | **0.69** |
| 2023/01〜2024/10 | 検証用 | 0.90 | 0.60 | **1.09** |
| 2024/11〜2026/08 | 最終OOS | 0.90 | **0.80** | **1.22** |

年別の加重平均で見ると 2022年の 0.648 が最安、2024年の 1.033 が最高。**変化は 2023年7月の段差**で起きている。

```text
2023-06  平均 0.62  最大 12.10
2023-07  平均 0.77  最大 20.50   ← ここで跳ねた
2023-08  平均 0.86  最大 20.50
```

- 平均と上限が**同時に階段状**に動いており、市場のボラティリティ由来とは考えにくい。ブローカーの提示条件の変更と見るのが自然
- 2024/11 以降は**最小値そのものが 0.60 → 0.80** に切り上がっている。下限が動く以上、これも提示条件の変更
- 高い水準は 2023/07 以降**3年間続いている**。IS 期間の 0.65 前後は戻ってこない過去の条件として扱う

**したがって、IS の成績を IS 期間のコストで判定してはいけない。** IS で「必要グロス 2.1 pips」をギリギリ超える設定を合格させると、検証用・最終OOS では必要グロスが 3.7 pips になって落ちる。`docs/backtest_design.md` の検証用は残弾が 2〜3 回しかないため、**最初から通らない設定でその残弾を消費することになる**。

IS のバックテスト自体は IS 期間のスプレッドで実行される（テスターがその期間のデータを使うため変えられない）。**変えるのは合否のライン**であり、IS で出たグロス期待値を 3.7 pips と比較する。

**時間帯の注意（2026-08-07 実測）**: サーバー時刻 **0時台（ロールオーバー）だけコストが跳ねる**。2023年Q1 の実測で中央値 2.80 pips・p90 5.70・p99 10.80 と、平常時（0.60）の **4.7倍**。R1 がこの時間帯で発火すると1トレードで必要グロス 2.1 pips を単独で吹き飛ばす。**時間帯フィルタは R1 の発火時刻の分布を見てから判断する**（先回りして入れない）。

**「1トレードあたりの最低利益」ではない** 【一意化】。トータル損益は

```text
トータル = 取引回数 N × ( 平均グロス損益 − 往復スプレッド )
```

なので、条件は**平均（期待値）がコストを上回ること**であって、個別トレードが毎回コストを超える必要はない。個々の負けトレードは想定内。

**逆に、勝ちトレードだけの平均を見てはいけない。** 前回の破棄はここを誤読して「グロスがプラスのセルが 80.1%」を優位性と解釈したのが発端（`docs/lessons_learned.md`）。

**×3 の根拠（数学ではなく判断）**: 損益分岐点は ×1 だが、次の3つが上乗せで効くため余裕を取る。**仮置きなので変えてよい**。

1. IS の数字は上振れする（閾値を触りながら出した値なので実運用では届かない）
2. 約定時のスプレッドは平均より広い（R1 はボラティリティが立ち上がる瞬間に発火するルール）
3. スリッページと手数料が別途乗る（往復スプレッドはコストの全部ではない）

> **正直に書いておく注意点**: TASK_MASTER には「トレンドフォロー寄りで保有が前回（M15 × 24本 = 6時間）より長くなればコスト不利は小さくなる見込み」とあるが、上表の想定保有は 50分〜5時間で**前回とほぼ同じか短い**。したがって**「保有が伸びるからコストを吸収できる」という期待は現時点で裏付けが無い**。優位性は保有時間ではなく獲得値幅（σ スケール）で確保する必要がある。**N0 は完了済み**（2026-08-07）で、残るのは IS の平均グロス損益との比較。

## 5. R2: スパンモデル 雲転換の順張り

### 5.1 スコープの制限 【一意化】

資料は「トレンド相場では順指標、**レンジ相場では逆指標**」と言う（p3）。しかし**レンジ判定はスーパーボリンジャーの仕事**（p3, p15）なので、逆指標の側を入れると SM 単体にならない。

→ **R2 では順張りのみ実装する。** レンジでの逆張りは R3（統合）で扱う。

### 5.2 エントリー 【資料】p5, S1 ＋ 【一意化】トリガーの割り当て

```text
買いエントリー（すべて AND、i = 1）:
  ① CloudFlip(1)           // 雲が赤→青へ転換            ← トリガー（S1「スパンAがスパンBを上回る＝買いシグナル」）
  ② LagAbove(1)            // 遅行スパンが陽転（p5-2, S1）
  ③ Close[1] > SpanA(1)    // ローソク足が青色スパンの上（p5-3）
  ④ SpanBUp(1)             // 赤色スパンが上向き（p5-1）

売りエントリー: CloudFlip の逆（青→赤）、LagBelow、Close < SpanA、SpanBDown
```

- p5 の4項目にそのまま対応させた。①を主トリガーにしたのは S1 が明示的に「シグナル」と呼んでいる唯一の条件だから
- ②③④は input で個別に ON/OFF できるようにする（フィルタの効き目を単独で測るため）

### 5.3 決済 【一意化】

資料はスパンモデル単体の決済を書いていない（p17 で「利食いの判断はスーパーボリンジャーを重ねると行いやすい」と述べており、**単体での利食い基準は事実上存在しない**）。

```text
買いの手仕舞い（いずれか先に成立したもの）:
  X1 雲の転換: CloudRed(1)                          // 買いシグナルの消滅
  X2 遅行の陰転: LagBelow(1)                         // input で ON/OFF
  X3 損切り: Bid ≤ EntryPrice − InpSLPips           // σ を持たないため pips 固定。**既定 OFF**
  X4 タイムストップ: InpHoldBars 本（既定 OFF）
```

**X3 が pips 固定なのは R1 と非対称** 【一意化】。SM は σ を計算しないため。R1 と条件を揃えたい場合のために、SM 側でも σ を計算する input（`InpUseSigmaSL`）を用意してもよいが、初版では pips 固定にして実装を軽くする。**損切り自体が既定 OFF**（2026-08-08、R1 と同じ）。使う場合の既定値は 20 pips（仮置き）で、往復コスト 1.22 pips の約 16 倍。R1 の 2.0σ と水準が揃うかは σ 次第なので IS で確認する。

> **ルール2の手仕舞いはルール1より遅い。** X1（雲の色の反転）は 9/26/52 本の中値から作る線の交差なので、逆行し続けても転換しない期間がある。損切り無しの影響はルール1より大きいはずで、**バックテストでの有無の比較はルール2でこそ重要**。

## 6. R3: 統合（R1/R2 の結果を見てから着手）

骨格だけ決めておく。詳細は R1/R2 の IS 結果を見てから `docs/` に追記する。

```text
上位足（H1）スーパーボリンジャー … 方向のフィルタ
  上昇局面 := Close[1] > σ1上(1)  または  R1 の買いが直近 N 本以内に成立している
  レンジ   := 終値が ±1σ の間で推移 かつ BW 縮小/フラット かつ LagInside   （p15）

下位足（M5）スパンモデル … タイミング
  上位が上昇局面 → R2 の買い条件で**順張り**             （p3「トレンド相場では順指標」）
  上位がレンジ   → 赤ゾーン接近で買い等の**逆張り**       （p3「レンジ相場では逆指標」）
  上位が下降局面 → 買いを取らない                        （p2「反対方向は慎重に」）
```

- 上の「レンジ」は p15 の文言をそのまま置いただけで、**まだ検算していない**。R1 で同じ形（終値と、同じ21本から作った ±1σ を比べる）が何も測っていないと判明しているので、着手時に §3.3 の `LagZ` へ置き換えるか確かめる
- 「反対方向は慎重に」（p2）は**取らない**と解釈する 【一意化】。ロット差で表現する案もあるが、可変ロットは検証を複雑にする
- 押し目買い／戻り売り（S1「スパンAへ接近」）は接近の定義（何 pips 以内か）が完全に裁量。**R3 の拡張候補**として保留

## 7. 【不採用】初版で実装しないもの

| 項目 | 出典 | 理由 |
|---|---|---|
| 押し目買い／戻り売り（スパンAへの接近） | S1 | 「接近」の距離が資料に無く、完全に裁量。R3 の拡張候補 |
| 「巡航速度」（±1σ〜±2σ 間の推移）の利用 | S1-2 | トレンドの**質**の記述で、エントリー／決済のタイミングではない |
| 移動平均の傾き＋横ばい化によるトレンド転換確認 | S1-1, S1-4 | R1 の4条件と役割が重複する。R1 が振るわなかった場合の代替案 |
| レンジ相場の値幅大小の区別（±2σ / ±1σ） | p15 | R3 まで使わない |
| 1分足の利用 | p2 | M5 でコスト予算を満たせない可能性が高い（前回の失敗領域）。M5 の結果を見てから |
| 可変ロット（大局観方向で厚く） | p2 | 検証が複雑になる。固定ロットで優位性の有無を先に判定する |
