セッションの軽量クローズを実行してください。引き継ぎノートの作成・セッション要約はしません（作業内容は context-mode が自動キャプチャするため）。**TASK_MASTER の進捗更新**、**次セッションへの確定事実の申し送り（記憶漏れ防止）**、**未コミット変更のコミット&プッシュ**を行います。

**本スキルは mql5-ea-lab ローカル限定**。対象は必ずリポジトリ直下の `tasks/TASK_MASTER.md` 固定パス（Globで他リポジトリを探索しない＝誤って別プロジェクト、特に D:\Antigravity\OLS-MeanReversion_MT5 配下のファイルを更新しないため）。git操作も必ず本リポジトリ（mql5-ea-lab）に対してのみ行う。

## ステップ 1: TASK_MASTER の進捗更新

1. 対象は `tasks/TASK_MASTER.md`（リポジトリルート基準）固定。存在しない場合は「tasks/TASK_MASTER.md が見つかりません」と報告し、ステップ 2 へ進む。
2. 今回のセッションで完了したタスクを `[ ]` → `[x]` に変更し、`— 完了 YYYY-MM-DD`（現在の日付）を追記する。PR を出した場合は `(PR #N)` も付ける。**寄り道の修正で `[x]` にせず、本来の成功基準を満たした時だけ完了とする**（未達なら `[ ]` のまま中断理由を一言追記）。
3. 今回新たに判明した制約・将来拡張があれば「運用知見メモ」セクションに 1 行で追記する。
4. **重要**: ここは要約を書く場所ではない。チェックボックスの更新と一行追記のみ。長い文章・物語は書かない（それが引き継ぎノートとの違いであり、コスト削減の肝）。

## ステップ 2: 次セッションへの申し合わせ（確定事実の埋込・記憶漏れ防止）

今セッションで「苦労して確定した／以前の理解を訂正した／非自明にコード・実測で判明した」事実を、次セッションが最初に読む場所（tasks/TASK_MASTER.md の先頭未完了タスク）へ出典付きで残す。**次セッションが同じことを再調査・再導出したり誤断定して時間を溶かすのを防ぐための前提の申し送り**であり、作業の要約ではない。

**発火条件（当てはまる時だけ実行。無ければスキップしステップ 3 へ）**: 今セッションで ①以前の理解や断定を訂正した ②非自明な事実をコード/実測で確定した ③試行錯誤の末に方針を決めた、のいずれかがある。単純作業のみのセッションはスキップ。

1. **対象の洗い出し**: 「次にこの領域を触る人が、知らなければ再調査・誤断定する事実」だけを選ぶ（全作業の要約はしない）。必要なら `ctx_search`（sort: timeline）で今セッションの訂正・決定・誤りの解消を引く（無ければ自分のセッション記憶から）。
2. **埋込先**: tasks/TASK_MASTER.md の**次に着手する未完了タスク**（`go` が先頭に出すもの）に `確定事実（再導出禁止・出典付き）` の小ブロックを付ける。各事実に**出典**（`file:line` / `docs/*` / メモリ名）を必ず添え、タスク見出しに「着手前に確定事実を読む・再導出禁止」の一言を入れる。
3. **恒久ルール**（作業横断の行動規範）は**メモリ**（feedback 型）へ保存し、tasks/TASK_MASTER.md からは `[[メモリ名]]` で参照する。
4. **肥大化ガード**: 簡潔・箇条書き・ポインタ主体。事実ブロックは該当タスクに紐付け、**タスク完了時に一緒に消える形**にする（グローバルな山を作らない）。古くなった申し送りは更新・削除する。ステップ 1 の「要約を書かない」原則と矛盾しない＝これは物語ではなく出典付きの短い事実ポインタ。

## ステップ 3: 未コミット変更のコミット&プッシュ

1. `git -C d:/repository/mql5-ea-lab status` で未コミットの変更を確認する（必ず本リポジトリのパスを明示。`cd` は使わない）。
2. **一時ファイル・意図しない生成物**（例: `tmp_*.py`、デバッグ出力、ローカル専用ファイル）が含まれていないか確認する。含まれる場合はコミット対象から外すか、ユーザーに確認する。
3. **`.mq5` / `.mqh` が含まれるか**で扱いが変わる:
   - **含まれない**（`docs/` `tasks/` `.claude/` `.gitignore` 等のみ）→ **main のまま直接コミット&プッシュしてよい**（PR不要）。
   - **含まれる** → main 上なら**先にブランチへ退避**する（`git switch -c feat/<topic>`。未コミット変更はそのまま持ち越される）。統合はステップ 3.5 の PR 経路。
4. 変更内容を反映した日本語のコミットメッセージを作成し、TASK_MASTER の更新も含めてステージング&コミット、`origin`（hiroa0809/mql5-ea-lab）へプッシュする。
5. 変更がない場合: 「未コミットの変更はありません」と報告する。

## ステップ 3.5: ブランチを main へ統合するか判断（毎回・スキップ禁止）

**目的**: ブランチを main に戻さず次の枝を切り続けると、未統合の枝が溜まり、いつか main から切って**先祖返り**する。区切りごとに必ず判断する。

現在ブランチが main ならスキップ（統合すべき枝がない）。feature ブランチ上なら:

1. **目的を達成したかユーザーに聞く**（自動判断しない）。判断材料に `git -C d:/repository/mql5-ea-lab log main..<branch> --oneline` を示す。
   - **作業途中** → 統合せず終了。報告に「未統合のまま継続」と明記し、次セッションが同じブランチに戻れるよう TASK_MASTER に一行残す。
2. **達成なら PR を作成**（`gh pr create --base main`）。feature ブランチ上にいる＝コードを含む変更なので、CodeRabbit レビューを経る。**本スキルではマージしない**（レビュー後に別途）。PR URL を報告し、ブランチも**残す**（マージ時に GitHub 側で削除）。

**マージ済みブランチの掃除**（PR がマージされた後のセッションで実施）:
```
git -C d:/repository/mql5-ea-lab branch --merged main    # マージ済みの枝を確認
git -C d:/repository/mql5-ea-lab branch -d <branch>      # -d は未マージなら拒否（-D は使わない）
```
**理由**: マージ済みの枝を残すと一覧が膨らみ、紛れた**未統合の枝を見落とす**（＝先祖返り事故の温床）。掃除すれば「一覧に残っている＝未統合の作業がある」となり、一覧が検知装置になる。コミットは main の履歴に残るため失われない（復活は `git switch -c <name> <ハッシュ>`）。

force push はしない。取り消しは `git revert`。次の作業は main から切る。

## 注意事項

- **本スキルは mql5-ea-lab ローカル限定**。git操作・ファイル更新は必ず本リポジトリ（`d:/repository/mql5-ea-lab`）に対してのみ行い、他プロジェクト（特に D:\Antigravity\OLS-MeanReversion_MT5）には一切触れない。
